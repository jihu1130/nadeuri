# 홈 화면 "지금 날씨"를 실제 관측값으로

## 한 일
- 홈 화면 위쪽 날씨 칸이 지금까지는 **예보** 값이었는데, 이제 기상청이 **실제로 관측한 값**(초단기실황)을 보여 줍니다.
  - 예: `지금 ☁️ 흐림 11° · 습도 83% · 강수 60%`
  - 기온·습도·지금 비나 눈이 오는지·최근 1시간 강수량 → 관측값
  - 하늘상태(맑음/구름많음/흐림)·강수확률 → 관측값에 없어서 예보에서 가져옴
  - 비가 오고 있으면 강수확률 대신 `1시간 1.5mm`처럼 강수량을 보여 줍니다.
  - 날씨 칸에 마우스를 올리면 `기상청 19:00 관측`처럼 관측 시각이 보입니다.
  - 관측값을 못 받으면 예전처럼 예보 값만 보여 주고, 앞에 `예보`라고 표시합니다.
- 휴대폰 너비에서는 `지금 ☁️ 흐림 11°`까지만 보입니다.

## 왜 이렇게 했나
- 예보만 쓰면 "비 예보"인데 실제로는 안 오는 경우가 그대로 보입니다. 오늘 여의도에서 예보는 "비"였지만 실제 관측은 비 없음이었고, 바뀐 화면은 "흐림"으로 보여 줍니다.
- 관측값은 매시 정시 기준으로 나오고, 오늘 확인해 보니 19:23에 19:00 값이 이미 나와 있었습니다. 그래서 정시 10분 뒤부터 그 시각 값을 부르고, 아직 없으면 한 시간 전 값을 씁니다.
- 같은 동네(격자)·같은 시각 값은 저장해 두고 다시 쓰므로 기상청을 너무 자주 부르지 않습니다.

## 확인한 것
- 기상청 API허브에 직접 요청해서 응답 모양을 확인했습니다 (인증키는 출력하지 않음).
- 테스트 66개 통과 (새로 12개: 응답 읽기, 결측값, 관측+예보 합치기, 한 시간 전으로 다시 시도, 국외 좌표).
- 새 코드를 :8899에 띄워 실제 응답과 화면(데스크톱, 휴대폰 너비)을 확인했습니다.

## 확인 방법
1. IntelliJ에서 앱을 재시작합니다.
2. http://localhost:8888 → 오른쪽 위 날씨 칸이 `지금 …`으로 시작하는지, 마우스를 올리면 관측 시각이 보이는지 확인합니다.

# 드롭다운(선택 목록) 디자인

## 한 일
- 홈의 **반경 선택**, 모임 만들기·수정의 **활동 종류**, **진행 시간** 목록을 앱 분위기(흰 바탕·노란 강조)에 맞게 바꿨습니다.
  - 펼친 목록이 둥근 카드 모양으로 뜨고, 고른 항목은 노란 배경 + ✓ 표시.
  - 활동 종류는 이모지가 노란 동그라미 안에 들어갑니다.
  - 화면 아래쪽에 공간이 없으면 위로 펼쳐집니다.
  - 키보드로도 쓸 수 있습니다(↑↓ 이동, Enter 선택, Esc 닫기, 글자 입력 시 해당 항목으로 이동).

## 사용한 기술과 이유
- 브라우저 기본 `<select>`의 펼친 목록은 CSS로 모양을 바꿀 수 없어서, 그 자리에 버튼과 목록을 만들어 보여 주는 작은 스크립트(`static/js/select-menu.js`)를 만들었습니다.
- 실제 값은 원래 `<select>`에 그대로 들어가므로 폼 전송·필수 입력 검사·기존 코드는 바뀌지 않습니다. 다른 화면에서도 `<select data-menu>`만 붙이면 같은 디자인이 됩니다.
- 로그인 설정이 `/js/` 주소를 막고 있어서(로그인 화면으로 보냄) `/js/**`를 로그인 없이 받을 수 있게 열었습니다. 테스트도 추가했습니다.

## 확인 방법
1. **IntelliJ에서 앱을 재시작**합니다 (로그인 설정이 바뀌어서 꼭 필요).
2. 홈에서 오른쪽 위 `반경 5km`를 눌러 목록 모양과 반경 변경을 확인합니다.
3. 로그인 후 모임 만들기에서 활동 종류·진행 시간을 눌러 확인합니다.

## 한 일

- **회원 탈퇴**: 내 모임 화면 맨 아래 `회원 탈퇴` → 지워질 내용 안내 → (아이디 회원은 비밀번호 확인) → 동의 체크 → 탈퇴. 만든 모임은 삭제되고, 참여한 모임에서는 빠집니다.

# 모임 채팅

## 한 일
- 모임에 참여한 사람(주최자 포함)끼리 **실시간으로 대화**할 수 있습니다.
  - 모임 상세 화면에 참여자에게만 **💬 모임 채팅** 버튼이 보입니다.
  - 채팅 화면: 최근 메시지 50개, 그 이전은 "이전 메시지 더 보기". 날짜가 바뀌면 구분선, 같은 사람이 이어서 보낸 글은 묶어서 보여 줍니다. 내 글은 오른쪽 노란 말풍선.
  - Enter로 보내기, Shift+Enter로 줄바꿈. 한 번에 500자까지.
  - 연결이 끊기면 1·2·4…초(최대 30초) 뒤 저절로 다시 연결하고, 그사이 놓친 메시지를 채웁니다.
- **참여한 사람만** 보고 쓸 수 있습니다. 참여를 취소하면 그 순간부터 새 메시지가 가지 않고 연결이 끊깁니다.
- 모임을 삭제하면 채팅 메시지도 함께 지워집니다.

## 사용한 기술과 이유
- **WebSocket**: 서버와 브라우저가 연결을 열어 두고 메시지를 바로 주고받는 방식. 처음 계획한 STOMP는 쓰지 않았습니다. 브라우저에 기본으로 있는 WebSocket만으로 충분해서 자바스크립트 라이브러리를 더 받을 필요가 없습니다 (Spring 의존성 `spring-boot-starter-websocket` 하나만 추가).
- **메시지 저장**: Flyway `V3__create_chat_message.sql`로 `chat_message` 테이블을 추가했습니다. 지난 메시지는 `GET /api/gatherings/{id}/messages`로 불러옵니다.
- **보안**: 로그인한 사람만 연결되고, 다른 사이트에서 몰래 연결하는 것은 막습니다. 사용자가 쓴 글은 HTML로 해석하지 않고 글자로만 보여 줍니다 (`<b>` 같은 태그도 그대로 보임).
- 지금은 서버가 한 대라서 채팅방 정보를 서버 메모리에 둡니다. 나중에 서버를 여러 대로 늘리면 Redis 같은 것이 필요합니다.

## 확인한 것
- 테스트 13개 추가 (실제 서버를 띄워 두 사람이 로그인해 메시지를 주고받는 테스트 포함). 세 번 반복해서 모두 통과. 전체 91개 통과.

# 주소의 번호를 UUID로 바꾸기

## 한 일
- 모임 주소가 `/gatherings/1`처럼 순번이었던 것을 `/gatherings/19b80fb1-6fbf-4450-8bcb-cefbbd653124`처럼 **무작위 UUID**로 바꿨습니다.
  - 상세, 수정, 참여, 참여 취소, 삭제, 채팅 화면, 지난 메시지 API, 채팅 WebSocket 주소 모두 바뀌었습니다.
  - 지도 API가 돌려주는 모임 `id`도 UUID입니다.
- **회원마다 UUID**도 만들었습니다. 채팅 메시지에 보낸 사람을 나타내던 회원 번호도 이제 UUID로 나갑니다. 나중에 프로필 주소에도 이 값을 씁니다.
- 예전 숫자 주소로 들어오면 "요청을 처리할 수 없어요"(400), 없는 UUID는 "찾는 모임이 없어요"(404) 화면이 나옵니다.

## 왜
- 주소에 1, 2, 3 같은 번호가 보이면 모임·회원 수를 짐작하거나 번호를 바꿔 넣어 다른 모임을 찾아볼 수 있습니다. 무작위 UUID는 짐작할 수 없습니다.
- DB 안에서는 여전히 순번을 씁니다 (빠르고, 기존 연결이 그대로 유지됨). 밖으로 보이는 값만 UUID입니다.

## 사용한 기술
- Flyway `V4__add_public_ids.sql`: 모임(`gathering`)과 회원(`users`)에 `public_id` 칸 추가, 이미 있던 행은 무작위 UUID로 채움. MySQL의 `UUID()`는 시간·장비 정보가 들어 있는 방식이라 쓰지 않고 무작위 값으로 만들었습니다.

## 확인한 것
- 테스트 96개 통과 (새로 5개: 숫자 주소 400, 없는 UUID 404, 링크에 순번 없음, 지도 API id, 채팅 API 주소).
- 기존 데이터가 있는 임시 DB에 V4를 적용해, 모든 행이 서로 다른 올바른 UUID로 채워지는 것을 확인하고 지웠습니다.
- 브라우저에서 UUID 주소로 모임 참여 → 채팅 → 메시지 보내기까지 확인했습니다.
- **실제 `nadeuri` DB에는 V4가 이미 적용되어 있습니다** (IntelliJ가 저절로 앱을 다시 시작함). V4 파일은 이제 고치면 안 됩니다.

## 알아 둘 점
- 예전에 공유한 숫자 주소 링크는 더 이상 열리지 않습니다 (지금은 실제 DB에 모임이 없어서 문제 없음).
