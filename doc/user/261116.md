# 2026-11-16 작업 일지

## 한 줄 요약
"지도 + 날씨로 동네 사람들과 함께할 모임 찾기" 아이디어를 기획하고, **Spring Boot + Thymeleaf 웹 서비스로 동작하는 첫 버전**을 만들었습니다. 기상청 날씨와 카카오맵을 연동하고, 코드 리뷰에서 나온 문제 6가지를 고친 뒤 프로젝트 구조까지 정리했습니다.

---

## 1. 기획

- **아이디어**: 지도와 날씨를 연동해서 동네 사람들이나 같은 목적을 가진 사람들과 특정 장소에서 행사·나들이를 함께할 사람을 찾는 서비스
- **차별점**: 날씨가 계기가 되는 즉흥(번개) 모임. "날씨 좋은데 근처에서 같이 나갈 사람?"
- **MVP 범위**: 지도 홈(주변 모임), 모임 만들기, 날씨 표시와 우천 경고, 참여하기
- **결정 사항**: 앱보다 **웹을 먼저** 만들기로 했습니다. 기술은 **Java + Spring Boot + Thymeleaf**, DB는 **MySQL**입니다.

## 2. 사용한 기술

| 영역 | 기술 | 이걸 고른 이유 |
|---|---|---|
| 백엔드 | Java 21, Spring Boot 3.3.5 | 직접 지정하신 기술 |
| 화면 | Thymeleaf + 순수 JavaScript | 서버 하나로 화면까지 처리할 수 있어 구조가 단순함 |
| DB | MySQL 8 (로컬 계정은 application-local.yml), 테스트는 H2 | 직접 지정. H2는 MySQL 없이 테스트하는 용도 |
| ORM | Spring Data JPA (Hibernate) | 엔티티 중심 개발 |
| 지도 | 카카오맵 JavaScript SDK | 국내 지도가 정확하고 장소 검색 API를 같이 쓸 수 있음 |
| 날씨 | 기상청 API허브 단기예보 (`getVilageFcst`) | 국내 기준이고 정확함, 무료 |
| 캐시 | Caffeine | 날씨 API 호출 횟수를 줄이기 위해 |
| 빌드 | Gradle 8.14 (Wrapper) | |

## 3. 진행 순서

### 3-1. 프로젝트 뼈대 만들기
- Spring Boot 프로젝트를 만들고 모임 엔티티, 반경 검색, 화면 3개(홈, 만들기, 상세)를 구현했습니다.
- 처음에는 키 없이 쓸 수 있는 Leaflet + OpenStreetMap 지도와 Open-Meteo 날씨로 시작했습니다.
- 작업 폴더의 파일이 사라지는 일이 있어서 다시 만들었고, 프로젝트를 **바탕화면 `nadeuri`** 폴더로 옮겼습니다.

### 3-2. MySQL로 전환
- PostgreSQL 설정을 MySQL로 바꿨습니다. `nadeuri` DB는 없으면 자동으로 만들어집니다.
- `server.port: 8888` 설정이 `spring:` 아래에 잘못 들어가 있어서 최상위로 옮겼습니다.

### 3-3. 기상청 API로 전환 + 코드 리뷰 6건 수정
| # | 문제 | 해결 |
|---|---|---|
| 1 | 서버 시간대에 따라 예보 시각이 어긋날 수 있음 | `Times.now()`로 항상 한국 시간(KST)을 쓰고, JVM과 DB 연결 시간대도 KST로 고정 |
| 2 | 동시에 참여하면 정원을 넘을 수 있음 | "자리 있을 때만 +1" 하는 단일 UPDATE 문으로 원자적으로 처리 |
| 3 | 같은 사람이 여러 번 참여할 수 있음 | `Participant` 테이블에 유니크 제약을 걸고, 게스트 쿠키로 사람을 구분 |
| 4 | 날짜변경선(±180°) 근처 검색 누락 | 경도 범위를 두 구간으로 나눠 조회하고, 극지방은 전체 경도를 대상으로 함 |
| 5 | 잘못된 좌표나 반경이 그대로 통과함 | 위도 ±90, 경도 ±180, 반경 100m~20km를 검증하고 벗어나면 400 에러 |
| 6 | DB 비밀번호가 설정 파일의 기본값으로 들어 있음 | `application-local.yml`과 `.env`로 분리하고 `.gitignore` 처리. 운영은 환경변수로 주입 |

- 위경도를 기상청 격자 좌표(nx, ny)로 바꾸는 변환 로직(`KmaGrid`)을 구현했습니다.

### 3-4. 기상청 키 발급 과정 (겪은 일)
- 처음 넣은 키는 공공데이터포털 키가 아니라 **기상청 API허브** 키였습니다. 그래서 코드를 API허브 주소와 `authKey` 파라미터에 맞게 바꿨습니다.
- API허브는 **기능마다 따로 활용신청**을 해야 했습니다.
  - "단기예보자료 조회", "격자자료", "통보문"은 우리가 쓰는 API가 아니었습니다.
  - 맞는 API는 **"동네예보(초단기실황·초단기예보·단기예보) 조회"** 안의 `getVilageFcst`입니다.
- 신청하고 승인이 반영되기까지 몇 분 동안 403 에러가 나왔다가 이후 정상으로 응답했습니다.
- 확인 결과: 서울 ⛅ 구름많음, 12°C, 강수확률 20%

### 3-5. 카카오맵으로 교체
- Kakao Developers에서 앱 "나들이"를 만들었습니다.
  - "앱 대표 도메인"은 localhost를 받아 주지 않아서 비워 뒀습니다.
  - JavaScript SDK 도메인에 `http://localhost:8888`을 등록했습니다.
  - 카카오맵 사용 설정을 ON으로 바꿨습니다.
- 바꾼 화면
  - **홈**: 카카오맵, 이모지 핀, 핀을 누르면 뜨는 정보창, 내 위치 표시
  - **모임 만들기**: 장소 검색(키워드), 지도를 클릭하면 주소 자동 입력, 선택한 장소의 날씨 미리보기
  - **상세**: 카카오맵 마커, "카카오맵에서 길찾기" 버튼
- 브라우저에서 세 화면이 모두 정상 동작하는 걸 확인했습니다.

### 3-6. 프로젝트 구조 정리
기능별 패키지 안을 역할별로 나눴습니다.
```
gathering / weather  →  controller, service, repository, domain, dto, exception, client
global               →  config, util, web, init
```
- 기상청 API 호출 코드는 `weather/client/KmaForecastClient`로 분리했습니다.
- `/api/weather` 응답을 `WeatherResponse` DTO로 바꿨습니다.

## 5. 알아 두면 좋은 점
- **lat / lng**: 위도(남북 위치) / 경도(동서 위치). 서울은 대략 37.57 / 126.97입니다.
- 기상청 단기예보는 **약 3일 뒤까지만** 나와서, 그보다 먼 모임은 "예보 없음"으로 표시됩니다.
- 참여자는 지금 **브라우저 쿠키**로 구분합니다. 쿠키를 지우면 새 사람으로 인식되므로, 카카오 로그인을 붙이면 해결됩니다.
- Java 코드를 수정한 뒤에는 IntelliJ에서 **앱을 재시작**해야 반영됩니다.
