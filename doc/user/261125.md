## 1. "이 지역에서 다시 검색" 목표 지점 깃발
- 지도를 끌어 옮겨서 **"↻ 이 지역에서 다시 검색"** 버튼이 나타나면, 지도 한가운데에 **노란 깃발**이 함께 꽂힙니다.
- 깃발의 깃대 끝이 꽂힌 자리가 바로 다시 검색할 기준점(지금 보이는 지도의 가운데)입니다.
- 지도를 계속 끌거나 확대·축소하면 깃발도 가운데를 따라 움직입니다.
- 버튼을 눌러 다시 검색하거나, 원래 검색한 곳 근처로 돌아오면 버튼과 함께 사라집니다.

### 사용한 기술
- 카카오 지도 `CustomOverlay`(지도 위에 직접 만든 표시를 올리는 기능)에 SVG 그림으로 깃발을 그렸습니다.
- 지도 가운데가 바뀔 때마다 오는 `center_changed` 이벤트로 깃발 위치를 옮깁니다.
- 깃발은 클릭을 막지 않도록 만들어서, 깃발 밑의 모임 핀도 그대로 누를 수 있습니다.

### 바뀐 파일
- `src/main/resources/static/js/home.js` — `syncResearchFlag()` 추가
- `src/main/resources/static/css/app.css` — `.research-flag` 모양·등장 애니메이션

### 확인 방법
1. IntelliJ에서 앱을 다시 빌드(또는 재시작)합니다. (바뀐 js·css를 불러오기 위해)
2. 홈 지도를 끌어서 다른 곳으로 옮깁니다.
3. 위쪽 버튼과 함께 지도 가운데에 노란 깃발이 보이는지, 버튼을 누르면 깃발 자리 기준으로 검색되는지 확인합니다.

## 2. 구글 로그인 추가
- 로그인 화면의 카카오 버튼 아래에 **"구글 계정으로 로그인"** 버튼이 생겼습니다.
- 구글로 처음 로그인하면 자동으로 회원가입되고, 다음부터는 같은 계정으로 들어옵니다. 구글 이름과 프로필 사진을 닉네임·사진으로 씁니다.
- 카카오 키와 구글 키는 따로 켜고 끌 수 있습니다. 구글 키가 비어 있으면 구글 버튼만 보이지 않고, 앱은 그대로 실행됩니다.

### 사용한 기술
- 카카오 로그인과 같은 Spring Security **OAuth2 Client**를 사용했습니다. 새로 추가한 라이브러리는 없습니다.
- 구글에는 **profile(이름·사진)** 권한만 요청합니다. 이메일은 받지 않습니다.
- 구글 계정마다 바뀌지 않는 번호(`sub`)로 회원을 구분합니다. 이메일은 바뀔 수 있어서 쓰지 않습니다.
- DB는 기존 `users` 테이블의 `provider` 칸에 `google`이라고 저장하므로 **테이블 변경이 없습니다.**

### 결정과 이유
- 카카오 전용이던 코드(`KakaoProfile`, `KakaoOAuth2UserService`)를 소셜 로그인 공통 코드(`SocialProfile`, `SocialOAuth2UserService`)로 바꿨습니다. 나중에 네이버 같은 로그인을 더할 때도 같은 자리에 추가하면 됩니다.
- 같은 사람이 카카오와 구글로 각각 로그인하면 지금은 **서로 다른 회원**이 됩니다. 계정을 하나로 합치는 기능은 아직 없습니다.

### 설정 방법 (직접 하셔야 합니다)
1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고 **API 및 서비스 → OAuth 동의 화면**을 설정합니다. (외부, 앱 이름 "나들이", 범위는 기본값)
2. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**를 누르고 유형을 **웹 애플리케이션**으로 고릅니다.
3. **승인된 리디렉션 URI**에 `http://localhost:8888/login/oauth2/code/google` 을 넣습니다.
4. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 `application-local.yml`에 넣습니다.
   ```yaml
   google:
     client-id: "..."
     client-secret: "..."
   ```
5. 앱을 다시 시작합니다.
- 동의 화면이 "테스트" 상태일 때는 **테스트 사용자로 등록한 구글 계정만** 로그인할 수 있습니다.

### 확인 방법
- 로그인 화면에 구글 버튼이 보이는지 확인합니다. 버튼을 누르면 구글 계정 선택 화면이 나오고, 로그인 후 원래 보던 화면으로 돌아오면 성공입니다.
- 테스트 105개가 모두 통과했습니다. 실제 구글 계정으로는 아직 확인하지 못했습니다. 키를 넣은 뒤 확인해야 합니다.

## 3. 다시 검색한 지점 표시 (주황 점)
- "이 지역에서 다시 검색"을 누르면 깃발은 사라지지만, 대신 그 자리에 **주황색 점**(옅은 주황 테두리)이 남습니다. 지도를 다른 곳으로 옮겨도 그 점은 검색한 자리에 그대로 있습니다.
- 내 위치(파란 점)와 헷갈리지 않도록 색을 다르게 했고, 지도 위쪽 범례에 **"검색 기준"** 항목이 함께 나타납니다.
- 내 위치 기준으로 검색할 때는 파란 점이 이미 그 자리이므로 주황 점과 범례 항목이 숨겨집니다. 위치를 못 찾아 여의도 기준으로 검색할 때는 여의도에 주황 점이 찍힙니다.

### 바뀐 파일
- `static/js/home.js` — `drawSearchArea()`가 기준점 표시까지 함께 그림
- `static/css/app.css` — `.search-center-marker`, `.legend-search-center`
- `templates/index.html` — 범례에 "검색 기준" 추가

### 확인 방법
1. 앱을 다시 빌드(또는 재시작)합니다. (템플릿도 바뀌었습니다)
2. 지도를 끌어 옮긴 뒤 "이 지역에서 다시 검색"을 누릅니다.
3. 검색한 자리에 주황 점이 남고, 범례에 "검색 기준"이 보이는지 확인합니다.

## 5. "내 위치에서 다시 검색" 버튼 + 검색 결과 필터

  - 활동 종류 버튼: 지금 결과에 있는 종류만 개수와 함께 보여 줍니다 (예: 🚶 산책 2).

  - 서버에 다시 묻지 않고 이미 받은 목록 안에서 거릅니다. 다시 검색해도 고른 필터는 유지됩니다.

## 5. 페이지를 옮길 때 상단바가 옆으로 밀리던 문제
- 원인: 홈처럼 긴 화면에는 오른쪽에 세로 스크롤바가 생기고, "내 모임"처럼 짧은 화면에는 생기지 않습니다. 스크롤바 폭(약 15px)만큼 화면 폭이 달라져서 상단바 오른쪽 메뉴가 움직였습니다.
- 해결: 스크롤바 자리를 항상 비워 두도록 했습니다 (`scrollbar-gutter: stable`). 상단바 여백도 화면 전체 폭(`100vw`, 스크롤바 포함) 대신 실제 내용 폭(`100%`)으로 계산합니다.
- 확인: 홈, 내 모임, 모임 만들기에서 로고와 메뉴 위치가 픽셀까지 같은지 재 봤습니다. 아직 커밋하지 않았습니다.

## 6. 필터·드롭다운·모임 개수 제한·기타 종류·지도 클릭 주소
- **활동 종류 버튼 전부 표시**: 홈 검색 결과 필터에 모든 활동 종류(산책~기타)가 늘 보입니다. 지금 결과에 없는 종류는 흐리게(개수 0) 보이고, 눌러 볼 수는 있습니다.
- **반경 고를 때 기본 목록 창이 뜨던 문제**: 반경 칸의 ⌖ 아이콘이나 여백을 누르면, 숨겨 둔 브라우저 기본 목록이 대신 열렸습니다(크롬이 라벨을 누르면 기본 목록을 여는 동작). 이제는 어디를 눌러도 꾸민 목록만 열립니다. 모임 만들기 화면의 "활동 종류" 같은 다른 드롭다운도 같이 고쳐졌습니다.
- **반경 칸과 "내 위치에서 다시 검색" 버튼 크기**: 둘 다 높이 40px로 맞추고, 반경 칸이 5px 아래로 내려가 있던 것(라벨 기본 여백)도 없앴습니다.
- **모임은 한 사람당 5개까지**: 아직 끝나지 않은(예정·진행 중) 모임을 5개 열어 둔 사람은 새 모임을 만들 수 없습니다. 모임 만들기 화면을 열면 위에 바로 안내가 나오고, 저장을 눌러도 막힙니다.
  - 끝난 모임은 세지 않습니다. 모임이 끝나거나 하나를 삭제하면 다시 만들 수 있습니다. (끝난 모임까지 세면 5개를 만든 뒤로 영영 못 만들게 되어 이렇게 정했습니다. 다르게 원하시면 말씀해 주세요)
  - 같은 사람이 동시에 여러 번 눌러도 5개를 넘지 않도록 서버에서 한 줄로 처리합니다.
- **활동 종류에 "📌 기타" 추가**: 비 예보 경고는 실내·야외를 알 수 없어서 띄우지 않습니다. DB의 활동 종류 목록도 함께 바꿨습니다(`V5__add_other_tag.sql`, 앱을 재시작하면 자동 적용).
- **지도에서 직접 위치를 찍으면**: 그 자리 주소가 **장소 검색 칸**에 들어가고, **모임 장소 이름 칸은 비워 둡니다**(직접 적어 주세요).

### 확인한 것
- 테스트 110개 통과 (모임 개수 제한 테스트 4개 추가).
- 임시 MySQL DB를 만들어 앱을 띄워서 V5 적용, "기타" 모임 저장, 6번째 모임이 막히는 것, 필터 버튼, 반경 목록, 버튼 높이를 확인한 뒤 임시 DB는 지웠습니다. 실제 `nadeuri` DB는 건드리지 않았습니다.
- **못 확인한 것**: 지도 클릭 → 주소 채우기는 카카오 지도가 8888 포트에서만 열려서 직접 눌러 보지 못했습니다. 재시작 후 모임 만들기 화면에서 지도를 한 번 눌러 확인해 주세요.

### 확인 방법
1. IntelliJ에서 앱을 재시작합니다 (Java·DB 변경이 있어 꼭 재시작).
2. 홈: 활동 종류 버튼이 모두 보이는지, 반경 칸 아이콘을 눌러도 꾸민 목록만 열리는지, 두 버튼 높이가 같은지 봅니다.
3. 모임 만들기: 활동 종류에 "📌 기타"가 있는지, 지도를 누르면 장소 검색 칸에 주소가 들어가고 장소 이름 칸은 비어 있는지 봅니다.

## 7. 모임 장소 오류 문구
- 장소를 고르지 않거나 이상한 값으로 저장하면 "널이어서는 안됩니다"가 두 번 나오던 것을 **"모임 장소를 선택해 주세요. 장소를 검색해 고르거나 지도에서 위치를 눌러 주세요."** 한 줄로 바꿨습니다.
  - 원인: 지도에서 고른 위치는 숨은 칸 두 개(위도·경도)에 들어가는데, 둘 다 비면 스프링 기본 문구가 칸마다 하나씩 나왔습니다.
- 다른 칸들(모임 이름, 시작 시간, 정원 등)의 오류도 한국어 안내로 바꿨고, 같은 문구는 한 번만 보이게 했습니다.
- 확인: 장소 없음·빈 값·숫자가 아닌 값·범위 밖 값 4가지를 테스트로 확인했습니다 (테스트 전체 통과). 앱을 재시작하면 반영됩니다.

## 8. 내 모임 개수 표시, 모임장 넘기기
- **"내가 만든 모임 3/5"**: 제목 옆에 끝나지 않은 모임 수 / 최대 5개를 보여 줍니다. 5개가 차면 빨간색으로 바뀝니다.
- **5개가 찼을 때 "+ 새 모임"**: 만들기 화면으로 가지 않고, 그 자리에 "모임은 한 사람당 5개까지 열 수 있어요…" 안내가 나옵니다.
- **모임장 넘기기**: 모임 상세에서 모임장에게 "모임장 넘기기"(참여자 고르기 → 넘기기)가 보입니다. 다른 참여자가 있으면 끝나기 전까지 언제든 넘길 수 있고, 삭제하지 않아도 됩니다.
  - 넘긴 사람은 일반 참여자로 남고, "참여한 모임"에 보입니다. 시작 전이면 참여 취소로 나갈 수 있습니다.
  - 받는 사람이 이미 모임을 5개 열어 두었으면 넘길 수 없습니다 (5개 제한을 지키기 위해).
  - 두 사람에게 동시에 넘겨도 모임장은 항상 한 명입니다.
- **삭제 규칙**: 나 말고 다른 참여자가 있는 모임은 삭제할 수 없고, 대신 "모임장을 넘긴 뒤 참여 취소로 나갈 수 있어요" 안내가 나옵니다. 혼자인 모임과 이미 끝난 모임은 지금처럼 삭제할 수 있습니다.
  - 회원 탈퇴할 때는 지금처럼 내가 만든 모임을 지웁니다(다른 참여자가 있어도). 탈퇴할 때 자동으로 다른 사람에게 넘기는 방식을 원하시면 말씀해 주세요.
- **"내가 만든 모임"을 "참여한 모임"에도 보여 줄지**: 같은 화면에 같은 모임이 두 번 나오게 되어 넣지 않았습니다. 대신 모임장을 넘기면 그 모임은 자연스럽게 "참여한 모임"으로 옮겨 갑니다.

### 확인한 것
- 테스트 전체 통과 (모임장 넘기기 7개, 화면 2개 추가, 삭제 규칙이 바뀐 기존 테스트 수정).

## 7. AI 도우미 (Gemini 무료 등급)
- 홈, 모임 상세, 내 모임, 모임 만들기 화면 오른쪽 아래에 **AI 도우미** 버튼이 생겼습니다. 로그인한 회원만 쓸 수 있습니다.
- "이번 주말 근처 산책 모임 있어?", "내일 피크닉 날씨 괜찮아?", "모임은 어떻게 만들어?" 같은 질문에 답합니다. 답에 모임이 나오면 **모임 보기** 링크가 붙습니다.
- 대화창 위쪽 노란 부분을 잡고 끌어서 옮길 수 있고, 두 번 누르면 원래 자리로 돌아갑니다.

### 동작 방식
1. 질문하면 서버가 먼저 사용자가 보고 있는 위치(상세 화면이면 모임 장소, 아니면 브라우저 위치, 모르면 여의도) 반경 5km의 모임과 기상청 예보를 조회합니다.
2. 그 자료와 대화 내용을 Google Gemini에 **한 번만** 보내 답을 받습니다. AI가 여러 번 조회를 주고받지 않아서 무료 사용량을 아끼고 더 안정적입니다.
3. 회원 닉네임·아이디는 보내지 않습니다. 무료 등급은 입력 내용이 구글 서비스 개선에 쓰일 수 있어서, 대화창 아래에 "개인정보는 적지 마세요" 안내를 넣었습니다.
4. 한 사람당 1분에 6번, 하루 100번까지 물어볼 수 있습니다 (무료 한도를 한 사람이 다 쓰지 않게).

### 사용한 기술
- Google Gemini API (Interactions API, 모델 `gemini-3.5-flash-lite`), Spring `RestClient` 로 직접 호출 (새 라이브러리 없음)
- Caffeine으로 횟수 제한, 대화 기록은 브라우저 탭(sessionStorage)에만 저장

### 설정
- `application-local.yml`의 `gemini.api-key` (Google AI Studio → Get API key). 비어 있으면 도우미 버튼이 나오지 않습니다.

### 확인
- 테스트 12개 추가, 통과. 실제 키로 Gemini 직접 호출 성공(한국어 답, 약 8.6초). 화면은 가짜 키로 :8899에서 확인했고, 실제 답변 화면은 직접 확인 중입니다. 아직 커밋하지 않았습니다.

## 9. 프로필 설정
- **들어가는 곳**: 상단바의 내 사진·닉네임을 누르거나, "내 모임" 아래 "프로필 설정"을 누릅니다. (`/me/profile`)
- **닉네임·자기소개 한 줄**: 닉네임은 20자, 자기소개는 100자까지. 자기소개는 모임 상세의 참여자 목록에서 닉네임 아래에 보입니다.
- **프로필 사진 올리기·지우기**: JPG·PNG·GIF, 5MB까지. 가운데를 정사각형으로 잘라 저장하고, 사진 속 촬영 위치(GPS) 같은 정보는 저장하지 않습니다. 지우면 닉네임 첫 글자 동그라미로 보입니다.
  - 사진 파일은 서버의 `uploads/profile` 폴더에 저장됩니다 (git에는 올라가지 않음). 서버를 옮길 때는 이 폴더도 함께 옮겨야 합니다.
- **비밀번호 바꾸기**: 아이디로 가입한 회원만 보입니다. 지금 비밀번호를 확인하고, 새 비밀번호는 가입할 때와 같은 규칙(8~64자, 영문+숫자)입니다.
- **카카오·구글 회원**: 예전에는 로그인할 때마다 카카오·구글의 닉네임·사진으로 다시 바뀌었는데, 이제 여기서 직접 바꾼 항목은 다시 로그인해도 그대로 유지됩니다.
- 바꾼 닉네임·사진은 다시 로그인하지 않아도 상단바에 바로 반영됩니다.
- DB에 칸 3개가 추가됩니다 (`V6__add_user_profile_settings.sql`, 앱 재시작 때 자동 적용).

### 확인한 것
- 테스트 140개 통과 (프로필 테스트 8개 추가: 닉네임·자기소개, 입력 오류, 카카오 재로그인 유지, 사진 저장·교체·삭제, 그림이 아닌 파일 거절, 경로 조작 무시, 비밀번호 바꾸기).

- 지도 높이는 400px → 약 610px로 커졌습니다.
- 목록 오른쪽에 얇은 스크롤바가 보여서 모임이 더 있다는 걸 알 수 있습니다.
- 휴대폰처럼 좁은 화면(지도 위·목록 아래)은 그대로입니다.
- 확인: 예시 모임 12개를 화면에만 넣어 PC 폭과 휴대폰 폭(375px)에서 확인했습니다. CSS만 바뀌어서 새로 고침하면 반영됩니다.

## 11. 확인 창을 사이트 모양으로
- 모임 삭제·모임장 넘기기·참여 취소·사진 지우기·회원 탈퇴 때 뜨던 브라우저 기본 확인 창("localhost:8888 내용:")을 사이트 색과 글꼴에 맞춘 창으로 바꿨습니다.
  - 굵은 제목(예: "모임을 삭제할까요?") + 설명 한 줄, 오른쪽 아래에 "취소"와 실제 할 일 버튼(예: "모임 삭제", "넘기기").
  - 삭제·탈퇴처럼 되돌릴 수 없는 일은 버튼이 빨간색입니다.
  - Esc, 창 바깥 누르기, "취소"는 아무 일도 하지 않습니다. 처음에는 "취소"에 초점이 있어서 Enter를 잘못 눌러도 안전합니다.
- 확인: 화면에 시험용 폼을 넣어 취소·Esc는 보내지 않고 확인만 한 번 보내는 것을 확인했습니다. 새로 고침하면 반영됩니다.
- 모임 만들기에서 장소를 안 골랐을 때 뜨는 알림 창도 아직 브라우저 기본 모양입니다. 원하시면 같은 모양으로 바꿀게요.

## 8. 채팅: 너무 빠른 전송 제한 + "입력 중" 표시
- **입력 중 표시**: 다른 사람이 메시지를 쓰고 있으면 입력칸 바로 위에 "○○님이 입력 중…"(점 세 개 깜빡임)이 보입니다. 두 명이면 "A님, B님이", 세 명 이상이면 "A님 외 2명이".
  - 보내거나, 다 지우거나, 3초 동안 안 치면 사라집니다. 연결이 끊긴 사람의 표시도 4초 뒤 저절로 사라집니다.
  - 저장하지 않고 실시간으로만 전달하며, 내 화면에는 내가 입력 중이라고 뜨지 않습니다.
- **전송 제한**: 1초 안에 5개를 넘게 보내면 3초 동안 보낼 수 없습니다.
  - 막힌 메시지는 저장되지 않고 입력칸에 그대로 돌아오며, "3초 뒤에 다시 보낼 수 있어요"처럼 남은 시간이 표시됩니다.
  - 서버에서 회원 기준으로 세기 때문에 탭을 여러 개 열어도 피해 갈 수 없습니다.

### 사용한 기술
- 기존 WebSocket에 새 신호 종류 추가: `typing`(입력 중), `rate_limited`(막힘)
- 전송 제한은 회원별 최근 1초 기록을 서버 메모리에 두고 계산 (서버를 다시 켜면 초기화)

### 확인
- 테스트 5개 추가, 전체 통과. 두 사람으로 로그인해 입력 중 표시, 보낸 뒤 사라짐, 6번 연속 전송 시 5개만 전달되고 6번째는 입력칸에 돌아오는 것, 3초 뒤 풀리는 것까지 화면에서 확인했습니다.

## 9. 로그인: 세션 로그인 + "로그인 상태 유지"
- 로그인은 원래부터 **세션 방식**이었습니다. 로그인하면 서버가 기억하고, 브라우저는 `JSESSIONID` 쿠키 하나만 가집니다. JWT는 쓰지 않습니다.
- 이번에 바꾼 것 (많은 사이트가 쓰는 방식):
  - **세션 설정을 정해 둠**: 30분 동안 아무것도 안 하면 로그아웃. 세션 쿠키는 스크립트가 못 읽고(HttpOnly), 다른 사이트에서 보낸 요청에는 실리지 않습니다(SameSite=Lax). 주소 뒤에 `;jsessionid=`가 붙지 않습니다.
  - **로그인 화면에 "로그인 상태 유지" 체크박스**: 체크하면 브라우저를 닫거나 30분 넘게 쉬어도 **14일 동안** 자동으로 다시 로그인됩니다. 공용 PC에서는 체크하지 마세요.
  - 자동 로그인 값은 DB(`remember_me_token` 표)와 맞춰 보고, 쓸 때마다 새 값으로 바뀝니다. 이미 쓴 예전 값이 다시 오면 도용으로 보고 그 회원의 자동 로그인을 모두 끊습니다.
  - **로그아웃·비밀번호 변경·탈퇴**를 하면 그 회원의 자동 로그인이 모든 기기에서 끊깁니다.
- 카카오·구글 로그인에는 체크박스가 없습니다(아이디 로그인만). 소셜 로그인은 버튼 한 번이면 다시 로그인되기 때문입니다.
- MySQL에는 서버를 다시 켜면 Flyway가 `V7` 표를 자동으로 만듭니다.

### 확인
- 테스트 6개 추가, 전체 151개 통과. 실제 서버에서 체크하고 로그인 → 세션 쿠키 없이 자동 로그인 쿠키만 들고 와도 로그인 필요한 화면이 열리고, 쿠키가 없으면 로그인 화면으로 가는 것을 확인했습니다.

## 10. 채팅: 내가 보낸 메시지 삭제
- 내 말풍선에 마우스를 올리면(휴대폰은 말풍선을 누르면) 옆에 작은 **삭제** 버튼이 보입니다.
- 누르면 사이트 모양의 확인 창이 뜨고, "삭제"를 누르면 **모든 참여자 화면에서 바로** "삭제된 메시지예요"로 바뀝니다.
- 남의 메시지에는 버튼이 없고, 서버에서도 보낸 사람만 지울 수 있게 막았습니다. 시간 제한은 두지 않았습니다.
- 지운 내용은 DB에서도 비워서 다시 볼 수 없습니다. 줄 자체는 남겨서 대화 순서와 날짜 구분이 그대로입니다.

### 사용한 기술
- `chat_message`에 `deleted_at` 칸 추가 (Flyway `V8`). 지우면 내용을 비우고 지운 시각을 적는 "소프트 삭제" 방식.
- 기존 WebSocket에 `delete`(지우기 요청) / `deleted`(지워졌다는 알림) 신호 추가.

### 확인
- 테스트 3개 추가, 전체 154개 통과.
- 임시 MySQL DB를 만들어 `V7`(로그인 상태 유지)과 `V8`이 실제 MySQL에서 잘 적용되는지 확인하고 지웠습니다. (사용 중인 `nadeuri` DB는 건드리지 않았습니다)
- 두 사람으로 로그인해 삭제 버튼 → 확인 창 → 양쪽 화면이 바로 바뀜, 새로 고침해도 유지, 남의 메시지에는 버튼 없음을 확인했습니다.
- 알아 둘 점: 연결이 끊겨 있던 동안 다른 사람이 지운 메시지는 새로 고침해야 "삭제된 메시지"로 보입니다.

## 11. 채팅방이 배경과 구분되게
- 채팅방 바깥은 한 톤 어두운 베이지, 채팅 칸은 둥근 모서리·테두리·그림자가 있는 카드로 띄웠습니다.
- 메시지 영역은 머리·입력칸보다 살짝 따뜻한 색이라 흰 말풍선이 또렷하게 보입니다. 휴대폰에서는 예전처럼 화면을 꽉 채웁니다.

## 12. 번개 모임
- **2시간 안에 시작하는 즉석 모임**입니다. 모임 만들기 화면의 "⚡ 번개 모임" 스위치를 켜면 날씨 달력 대신 **10분 뒤 · 30분 뒤 · 1시간 뒤 · 1시간 30분 뒤 · 2시간 뒤** 버튼으로 시작 시간을 고릅니다 (켜면 30분 뒤가 먼저 골라져 있음).
  - "30분 뒤"는 **저장 버튼을 누른 때부터** 30분 뒤로 다시 맞춰집니다. 화면을 오래 열어 두어도 어긋나지 않습니다.
  - 스위치를 끄면 날씨 달력에서 골라 두었던 시간으로 돌아갑니다.
- 서버도 확인합니다: 번개 모임인데 시작이 2시간보다 뒤면 "번개 모임은 지금부터 2시간 안에 시작해야 해요" 안내와 함께 다시 입력받습니다. 모임 수정에서도 번개를 켜고 끌 수 있습니다.
- 보이는 곳
  - **지도**: 어두운 핀 + 노란 ⚡ 딱지 + 퍼져 나가는 노란 테두리로 번쩍입니다. 일반 핀보다 위에 그려집니다.
  - **모임 목록**: "⚡ 번개" 배지와 어두운 아이콘. 필터에 **"⚡ 번개만"** 체크칸을 추가했습니다.
  - **모임 상세**: 활동 종류 옆에 "⚡ 번개" 배지.
- 끝나는 시간이 지나면 다른 모임처럼 저절로 검색에서 빠집니다. 1인 5개 제한에도 똑같이 들어갑니다.
- 함께 고친 것: 모임 만들기에서 장소를 안 고르고 등록을 누르면 뜨는 안내가 **그동안 실제로는 뜨지 않았습니다** (화면 위쪽 로그아웃 폼에 걸려 있었음). 이제 모임 폼에 제대로 걸려서 뜹니다.

### 사용한 기술
- `gathering` 표에 `flash` 칸 추가 (Flyway `V9`, 기존 모임은 모두 일반 모임).
- 서버 검사는 요청 값 검사(`@AssertTrue`)로, 저장 직전 시각 기준 2시간 + 여유 10분.

### 확인
- 테스트 5개 추가, 전체 통과.
- 임시 MySQL DB에서 `V9`까지 잘 적용되는지 확인하고 지웠습니다 (사용 중인 `nadeuri` DB는 건드리지 않음).
- 화면: 스위치 켜기 → 달력이 숨고 버튼이 보임, "1시간 뒤"로 등록 → 상세·목록에 번개 배지, 번개 핀 모양을 확인했습니다. 실제 카카오 지도 위 핀은 8888 서버를 다시 켠 뒤 직접 봐 주세요.

## 13. 끝난 모임 후기와 평판 ("다음에 또 만나요")
- 모임이 끝나면 상세 화면에 **모임 후기** 칸이 생깁니다. 그 모임에 참여한 사람은 **별점(1~5개) + 한 줄 후기(선택, 200자)**를 남길 수 있고, 다시 쓰면 고쳐집니다. 내 후기는 지울 수도 있습니다(사이트 모양 확인 창).
- 참여자 목록에서 함께한 사람마다 **👋 또 만나요** 버튼이 생깁니다. 누르면 보내고, 다시 누르면 거둡니다. 좋은 표시만 있고 나쁜 표시는 없습니다.
- 후기와 "또 만나요"는 **모임이 끝나고 14일 동안**만 남길 수 있습니다. 지난 뒤에도 남긴 후기는 계속 보입니다.
- **평판**은 이렇게 보입니다.
  - 모든 모임 상세의 참여자 이름 아래: "👋 또 만나요 3 · ★ 모임장 4.5 (6)". 모임에 참여할지 고를 때 참고할 수 있습니다.
  - 프로필 설정의 **내 평판**: 받은 "또 만나요" 수, 내가 연 모임의 별점 평균.
  - 모임장 별점은 그 사람이 연 모임에 **다른 참여자들이** 준 별점의 평균입니다(모임장 자신의 별점은 빠짐).
- 내 모임 화면의 끝난 모임에 아직 후기를 안 썼으면 **✍ 후기 남기기** 표시가 붙고, 누르면 바로 후기 칸으로 갑니다.
- 모임을 지우면 그 모임의 후기·"또 만나요"도 함께 지워지고, 탈퇴하면 그 사람이 쓴 후기와 보내고 받은 "또 만나요"가 지워집니다.

### 사용한 기술
- 새 표 `gathering_review`(한 사람이 한 모임에 하나), `meet_again` (Flyway `V10`).
- 같은 사람이 여러 번 빨리 눌러도 한 줄만 남도록 회원 행을 잠그고 처리.

### 확인
- 테스트 10개 추가, 전체 173개 통과.
- 임시 MySQL DB에서 `V10`(그리고 다른 작업의 `V12`)까지 잘 적용되는지 확인하고 지웠습니다. 사용 중인 `nadeuri` DB는 건드리지 않았습니다.
- 화면: 끝난 모임에서 별 4개 + 후기 저장 → 고치기 화면으로 바뀜, 또 만나요 보내기 → "보냈어요" + 모임장 평판 표시, 내 모임의 "후기 남기기", 프로필의 내 평판을 확인했습니다.
- 알아 둘 점: DB 번호 정리 — 번개 모임 `V9`, 후기 `V10`, 채팅 메시지 수정(다른 작업) `V12`. `V11`은 비어 있어도 괜찮습니다.
