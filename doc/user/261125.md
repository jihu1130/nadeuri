# 2026-11-25 작업 기록

## 1. "이 지역에서 다시 검색" 목표 지점 깃발
- 지도를 끌어 옮겨서 **"↻ 이 지역에서 다시 검색"** 버튼이 나타나면, 지도 한가운데에 **노란 깃발**이 함께 꽂힙니다.
- 깃발의 깃대 끝이 꽂힌 자리가 바로 다시 검색할 기준점(지금 보이는 지도의 가운데)입니다.
- 지도를 계속 끌거나 확대·축소하면 깃발도 가운데를 따라 움직입니다.
- 버튼을 눌러 다시 검색하거나, 원래 검색한 곳 근처로 돌아오면 버튼과 함께 사라집니다.

### 사용한 기술
- 카카오 지도 `CustomOverlay`(지도 위에 직접 만든 표시를 올리는 기능)에 SVG 그림으로 깃발을 그렸습니다.
- 지도 가운데가 바뀔 때마다 오는 `center_changed` 이벤트로 깃발 위치를 옮깁니다.
- 깃발은 클릭을 막지 않도록 만들어서, 깃발 밑의 모임 핀도 그대로 누를 수 있습니다.

### 바뀐 파일
- `src/main/resources/static/js/home.js` — `syncResearchFlag()` 추가
- `src/main/resources/static/css/app.css` — `.research-flag` 모양·등장 애니메이션

### 확인 방법
1. IntelliJ에서 앱을 다시 빌드(또는 재시작)합니다. (바뀐 js·css를 불러오기 위해)
2. 홈 지도를 끌어서 다른 곳으로 옮깁니다.
3. 위쪽 버튼과 함께 지도 가운데에 노란 깃발이 보이는지, 버튼을 누르면 깃발 자리 기준으로 검색되는지 확인합니다.

## 2. 구글 로그인 추가
- 로그인 화면의 카카오 버튼 아래에 **"구글 계정으로 로그인"** 버튼이 생겼습니다.
- 구글로 처음 로그인하면 자동으로 회원가입되고, 다음부터는 같은 계정으로 들어옵니다. 구글 이름과 프로필 사진을 닉네임·사진으로 씁니다.
- 카카오 키와 구글 키는 따로 켜고 끌 수 있습니다. 구글 키가 비어 있으면 구글 버튼만 보이지 않고, 앱은 그대로 실행됩니다.

### 사용한 기술
- 카카오 로그인과 같은 Spring Security **OAuth2 Client**를 사용했습니다. 새로 추가한 라이브러리는 없습니다.
- 구글에는 **profile(이름·사진)** 권한만 요청합니다. 이메일은 받지 않습니다.
- 구글 계정마다 바뀌지 않는 번호(`sub`)로 회원을 구분합니다. 이메일은 바뀔 수 있어서 쓰지 않습니다.
- DB는 기존 `users` 테이블의 `provider` 칸에 `google`이라고 저장하므로 **테이블 변경이 없습니다.**

### 결정과 이유
- 카카오 전용이던 코드(`KakaoProfile`, `KakaoOAuth2UserService`)를 소셜 로그인 공통 코드(`SocialProfile`, `SocialOAuth2UserService`)로 바꿨습니다. 나중에 네이버 같은 로그인을 더할 때도 같은 자리에 추가하면 됩니다.
- 같은 사람이 카카오와 구글로 각각 로그인하면 지금은 **서로 다른 회원**이 됩니다. 계정을 하나로 합치는 기능은 아직 없습니다.

### 설정 방법 (직접 하셔야 합니다)
1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고 **API 및 서비스 → OAuth 동의 화면**을 설정합니다. (외부, 앱 이름 "나들이", 범위는 기본값)
2. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**를 누르고 유형을 **웹 애플리케이션**으로 고릅니다.
3. **승인된 리디렉션 URI**에 `http://localhost:8888/login/oauth2/code/google` 을 넣습니다.
4. 만들어진 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 `application-local.yml`에 넣습니다.
   ```yaml
   google:
     client-id: "..."
     client-secret: "..."
   ```
5. 앱을 다시 시작합니다.
- 동의 화면이 "테스트" 상태일 때는 **테스트 사용자로 등록한 구글 계정만** 로그인할 수 있습니다.

### 확인 방법
- 로그인 화면에 구글 버튼이 보이는지 확인합니다. 버튼을 누르면 구글 계정 선택 화면이 나오고, 로그인 후 원래 보던 화면으로 돌아오면 성공입니다.
- 테스트 105개가 모두 통과했습니다. 실제 구글 계정으로는 아직 확인하지 못했습니다. 키를 넣은 뒤 확인해야 합니다.

## 3. 다시 검색한 지점 표시 (주황 점)
- "이 지역에서 다시 검색"을 누르면 깃발은 사라지지만, 대신 그 자리에 **주황색 점**(옅은 주황 테두리)이 남습니다. 지도를 다른 곳으로 옮겨도 그 점은 검색한 자리에 그대로 있습니다.
- 내 위치(파란 점)와 헷갈리지 않도록 색을 다르게 했고, 지도 위쪽 범례에 **"검색 기준"** 항목이 함께 나타납니다.
- 내 위치 기준으로 검색할 때는 파란 점이 이미 그 자리이므로 주황 점과 범례 항목이 숨겨집니다. 위치를 못 찾아 여의도 기준으로 검색할 때는 여의도에 주황 점이 찍힙니다.

### 바뀐 파일
- `static/js/home.js` — `drawSearchArea()`가 기준점 표시까지 함께 그림
- `static/css/app.css` — `.search-center-marker`, `.legend-search-center`
- `templates/index.html` — 범례에 "검색 기준" 추가

### 확인 방법
1. 앱을 다시 빌드(또는 재시작)합니다. (템플릿도 바뀌었습니다)
2. 지도를 끌어 옮긴 뒤 "이 지역에서 다시 검색"을 누릅니다.
3. 검색한 자리에 주황 점이 남고, 범례에 "검색 기준"이 보이는지 확인합니다.

## 5. "내 위치에서 다시 검색" 버튼 + 검색 결과 필터
- **내 위치에서 다시 검색**: "반경 안의 모임" 오른쪽, 반경 선택 옆에 노란 버튼이 생겼습니다. 누르면 위치를 새로 찾고, 지도를 내 위치로 옮긴 뒤 그 자리 기준으로 다시 검색합니다. (지도 안 ⌖ 버튼은 지금처럼 이동만 합니다)
- **검색 결과 필터** (오른쪽 모임 목록 위):
  - 검색창: 모임 이름·장소·활동 종류로 찾습니다.
  - 활동 종류 버튼: 지금 결과에 있는 종류만 개수와 함께 보여 줍니다 (예: 🚶 산책 2).
  - "모집 중만": 모집 마감·진행 중인 모임을 뺍니다.
  - 필터는 목록과 지도 핀에 함께 적용되고, 개수는 `2/4개`처럼 표시됩니다. 맞는 모임이 없으면 "필터 초기화" 버튼이 나옵니다.
  - 서버에 다시 묻지 않고 이미 받은 목록 안에서 거릅니다. 다시 검색해도 고른 필터는 유지됩니다.

### 바뀐 파일
- `templates/index.html`, `static/js/home.js`, `static/css/app.css`

### 확인 방법
1. 앱을 다시 빌드(또는 재시작)합니다.
2. 홈에서 "내 위치에서 다시 검색"을 눌러 내 위치 기준으로 검색되는지 봅니다.
3. 모임이 있는 지역에서 검색어·활동 종류·모집 중만을 바꿔 보며 목록과 지도 핀이 같이 바뀌는지 확인합니다.

## 4. 로그인 버튼 아이콘, 상단바 회원가입 버튼

- 확인: 테스트 통과, 화면은 PC 폭과 휴대폰 폭(375px)에서 확인했습니다. 아직 커밋하지 않았습니다.

## 5. 페이지를 옮길 때 상단바가 옆으로 밀리던 문제
- 원인: 홈처럼 긴 화면에는 오른쪽에 세로 스크롤바가 생기고, "내 모임"처럼 짧은 화면에는 생기지 않습니다. 스크롤바 폭(약 15px)만큼 화면 폭이 달라져서 상단바 오른쪽 메뉴가 움직였습니다.
- 해결: 스크롤바 자리를 항상 비워 두도록 했습니다 (`scrollbar-gutter: stable`). 상단바 여백도 화면 전체 폭(`100vw`, 스크롤바 포함) 대신 실제 내용 폭(`100%`)으로 계산합니다.
- 확인: 홈, 내 모임, 모임 만들기에서 로고와 메뉴 위치가 픽셀까지 같은지 재 봤습니다. 아직 커밋하지 않았습니다.


## 6. 필터·드롭다운·모임 개수 제한·기타 종류·지도 클릭 주소
- **활동 종류 버튼 전부 표시**: 홈 검색 결과 필터에 모든 활동 종류(산책~기타)가 늘 보입니다. 지금 결과에 없는 종류는 흐리게(개수 0) 보이고, 눌러 볼 수는 있습니다.
- **반경 고를 때 기본 목록 창이 뜨던 문제**: 반경 칸의 ⌖ 아이콘이나 여백을 누르면, 숨겨 둔 브라우저 기본 목록이 대신 열렸습니다(크롬이 라벨을 누르면 기본 목록을 여는 동작). 이제는 어디를 눌러도 꾸민 목록만 열립니다. 모임 만들기 화면의 "활동 종류" 같은 다른 드롭다운도 같이 고쳐졌습니다.
- **반경 칸과 "내 위치에서 다시 검색" 버튼 크기**: 둘 다 높이 40px로 맞추고, 반경 칸이 5px 아래로 내려가 있던 것(라벨 기본 여백)도 없앴습니다.
- **모임은 한 사람당 5개까지**: 아직 끝나지 않은(예정·진행 중) 모임을 5개 열어 둔 사람은 새 모임을 만들 수 없습니다. 모임 만들기 화면을 열면 위에 바로 안내가 나오고, 저장을 눌러도 막힙니다.
  - 끝난 모임은 세지 않습니다. 모임이 끝나거나 하나를 삭제하면 다시 만들 수 있습니다. (끝난 모임까지 세면 5개를 만든 뒤로 영영 못 만들게 되어 이렇게 정했습니다. 다르게 원하시면 말씀해 주세요)
  - 같은 사람이 동시에 여러 번 눌러도 5개를 넘지 않도록 서버에서 한 줄로 처리합니다.
- **활동 종류에 "📌 기타" 추가**: 비 예보 경고는 실내·야외를 알 수 없어서 띄우지 않습니다. DB의 활동 종류 목록도 함께 바꿨습니다(`V5__add_other_tag.sql`, 앱을 재시작하면 자동 적용).
- **지도에서 직접 위치를 찍으면**: 그 자리 주소가 **장소 검색 칸**에 들어가고, **모임 장소 이름 칸은 비워 둡니다**(직접 적어 주세요).

### 확인한 것
- 테스트 110개 통과 (모임 개수 제한 테스트 4개 추가).
- 임시 MySQL DB를 만들어 앱을 띄워서 V5 적용, "기타" 모임 저장, 6번째 모임이 막히는 것, 필터 버튼, 반경 목록, 버튼 높이를 확인한 뒤 임시 DB는 지웠습니다. 실제 `nadeuri` DB는 건드리지 않았습니다.
- **못 확인한 것**: 지도 클릭 → 주소 채우기는 카카오 지도가 8888 포트에서만 열려서 직접 눌러 보지 못했습니다. 재시작 후 모임 만들기 화면에서 지도를 한 번 눌러 확인해 주세요.

### 확인 방법
1. IntelliJ에서 앱을 재시작합니다 (Java·DB 변경이 있어 꼭 재시작).
2. 홈: 활동 종류 버튼이 모두 보이는지, 반경 칸 아이콘을 눌러도 꾸민 목록만 열리는지, 두 버튼 높이가 같은지 봅니다.
3. 모임 만들기: 활동 종류에 "📌 기타"가 있는지, 지도를 누르면 장소 검색 칸에 주소가 들어가고 장소 이름 칸은 비어 있는지 봅니다.

## 6. 구글 로그인 실제 확인 완료
- `application-local.yml`에 구글 키를 넣고 :8888을 재시작한 뒤, 실제 구글 계정으로 로그인에 성공했습니다.
- DB `users` 테이블에 `provider = google` 회원 1명이 생기고, 프로필 사진도 저장된 것을 확인했습니다. (읽기만 했습니다)
- 참고: 구글 동의 화면이 "테스트" 상태이면 테스트 사용자로 등록한 계정만 로그인할 수 있습니다. 다른 사람도 쓰게 하려면 Google Cloud Console에서 앱을 **게시(프로덕션)** 상태로 바꿔야 합니다.


## 7. 모임 장소 오류 문구
- 장소를 고르지 않거나 이상한 값으로 저장하면 "널이어서는 안됩니다"가 두 번 나오던 것을 **"모임 장소를 선택해 주세요. 장소를 검색해 고르거나 지도에서 위치를 눌러 주세요."** 한 줄로 바꿨습니다.
  - 원인: 지도에서 고른 위치는 숨은 칸 두 개(위도·경도)에 들어가는데, 둘 다 비면 스프링 기본 문구가 칸마다 하나씩 나왔습니다.
- 다른 칸들(모임 이름, 시작 시간, 정원 등)의 오류도 한국어 안내로 바꿨고, 같은 문구는 한 번만 보이게 했습니다.
- 확인: 장소 없음·빈 값·숫자가 아닌 값·범위 밖 값 4가지를 테스트로 확인했습니다 (테스트 전체 통과). 앱을 재시작하면 반영됩니다.
