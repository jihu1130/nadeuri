## Architecture
Package-by-feature, then by layer: `com.example.nadeuri.{gathering,weather,user,global}.{controller,service,repository,domain,dto,exception,client,config,security,util,init}`. See README "프로젝트 구조" for the full tree.

Key decisions (keep unless owner asks):
- Time: always `Times.now()` (KST). JVM default TZ set to Asia/Seoul in `main`; Hibernate `jdbc.time_zone=Asia/Seoul`.
- Radius search: native SQL haversine + bounding box; longitude split into two ranges across the antimeridian; full longitude near poles. Works on MySQL and H2. Radius clamped 100–20000 m.
- Join: first `UPDATE ... SET current_people = current_people + 1 WHERE current_people < max_people` (0 rows → `IllegalStateException`, nothing inserted), then insert `Participant` (unique `(gathering_id, user_id)`, no FK to users); a duplicate violation rolls back the increment too. Order changed 2026-11-18: insert-then-rollback on full gatherings made H2 reuse identity values under concurrency → flaky PK violations in the 20-thread test. Host gets a Participant row on create. Sample data has no host rows (fine).
- Identity: Kakao + Google login via Spring Security `oauth2Login`. `global/config/SecurityConfig.clientRegistrationRepository` registers Kakao when `kakao.rest-api-key` is non-blank and Google when both `google.client-id` and `google.client-secret` are non-blank; the bean exists only if at least one is set (`@ConditionalOnExpression`), otherwise oauth2Login is skipped and `/login` shows a "소셜 로그인 사용 불가" notice — the app still boots without keys. `LoginController` exposes `kakaoEnabled` / `googleEnabled` per registration. Kakao: client auth `client_secret_post`, scopes `profile_nickname, profile_image`. Google: `CommonOAuth2Provider.GOOGLE` with scope **`profile` only** (no `openid` → plain OAuth2, not OIDC, so `OidcUserService` is not used and `LoginUser` needs no `OidcUser`; no `email`). Google redirect URI `{baseUrl}/login/oauth2/code/google`.
- Local (아이디 + password) login — switched from email to username on 2026-11-18 at owner request: `formLogin` on POST `/login` with params `username`/`password`; failure → `/login?error=local` (Kakao failures → `/login?error`). `LocalUserDetailsService` looks up `users` where provider=`local`, provider_id=normalized username (strip + lowercase). Passwords hashed with `PasswordEncoderFactories.createDelegatingPasswordEncoder()` (`{bcrypt}...`, static bean in SecurityConfig). Signup `/signup` (`SignUpRequest`: username `^[A-Za-z][A-Za-z0-9_]{3,19}$`, password 8–64 with letter+digit, confirm, nickname ≤20) → `UserService.signUp` → redirect to `/login` with flash message + prefilled username (no auto-login, so the saved request survives). Success handler updates `last_login_at` and redirects to the saved request. `LoginUser` implements both `OAuth2User` and `UserDetails` + `CredentialsContainer` (hash erased after auth, not kept in session).
- Social login flow: `user/service/SocialOAuth2UserService` (switch on registrationId) → `SocialProfile.kakao(attrs)` / `SocialProfile.google(attrs)` (Google id = `sub`, nickname = `name` → `given_name` → default, image = `picture`) → `UserService.loginWithSocial` (upsert by provider + providerId into table `users`; provider `kakao` | `google` | `local`, no migration needed) → principal `global/security/LoginUser` (Serializable, holds our `users.id`, nickname, image). Controllers take `@AuthenticationPrincipal LoginUser`. `ViewModelAdvice` exposes `loginUser` to all views; header fragment `templates/fragments/auth.html`. Thymeleaf SpEL needs `${loginUser != null ...}` inside boolean expressions.
- Local, Kakao and Google accounts are separate (no linking yet). Accounts created during the short email period have provider_id = email; they still log in by typing the email in the 아이디 field (lookup is not validated against the username pattern).
- Access: GET `/`, `/gatherings/*`, `/api/**`, `/login`, `/signup`, `/.well-known/**`, static → public. Custom `HttpSessionRequestCache` (SecurityConfig.REQUEST_CACHE, shared with formLogin/oauth2Login success) saves only GET page requests — excludes `/.well-known`, `/api`, `/error`, static, h2-console, XHR — because Chrome DevTools auto-requests `/.well-known/appspecific/com.chrome.devtools.json` and the default cache made login redirect there (bug found 2026-11-18). `/gatherings/new`, POST create/join, GET `/gatherings/{id}/sign-in` → login required (entry point `/login`). `/sign-in` exists so the request cache saves a GET and returns the user to the detail page after login (POST isn't cached). Matchers use `antMatcher` (H2 console servlet makes string matchers ambiguous). CSRF on; forms must use `th:action` so the token is injected. (The earlier `UserDetailsServiceAutoConfiguration` exclusion was removed; our `LocalUserDetailsService` bean replaces it.)
- Weather: `KmaForecastClient.fetch(nx, ny, base)` is `@Cacheable("weather")` keyed by grid + base time; `latestBaseTime` = latest of 02,05,…,23 with 10-min availability lag. `WeatherService.forecastAt` picks nearest hour within ±2h. Short-term forecast covers ~3 days only.
- Home "지금 날씨" (2026-11-23): `KmaNowcastClient` (`kma.nowcast-url` = getUltraSrtNcst, same key) `@Cacheable(value="nowcast", unless="#result == null")` keyed by grid + base hour; base = (now − 10 min) truncated to the hour, `WeatherService.current` retries one hour earlier if null. Not-yet-published base → HTTP 200 + resultCode "10"; missing values like -998.9 → null. `CurrentWeather` = nowcast T1H/REH/PTY/RN1 + forecast SKY/POP (nowcast PTY wins; nowcast-only → "비 없음" 🌡️; no nowcast → old forecast behaviour). `WeatherInfo` PTY now also 5 빗방울 / 6 빗방울·눈날림 / 7 눈날림. `/api/weather` = `WeatherResponse` (adds humidity, rain1h, observed, observedAt; nullable Integer for unknown). Home chip: "지금 ☁️ 흐림 11° · 습도 83% · 강수 60%" (or "1시간 Nmm" when raining; "예보" label when no nowcast), title = "기상청 HH:00 관측".
- Chat (2026-11-23): plain Spring WebSocket (no STOMP, no client lib — browser `WebSocket`). Endpoint `/ws/gatherings/*/chat` (`global/config/WebSocketConfig`, default same-origin check; not in SecurityConfig permit list → handshake needs login). `chat/websocket/ChatWebSocketHandler`: on connect checks `ChatService.canChat` (participant row incl. host) else closes 1008; in-memory rooms `Map<gatheringId, Set<ConcurrentWebSocketSessionDecorator>>` (single server only); inbound `{"content"}` → `ChatService.send` (strip, 1–500 chars) → broadcast `{"type":"message","message":ChatMessageView}`; errors only to sender `{"type":"error"}`; every broadcast re-reads `members()` and closes sessions of people who left. Table `chat_message` (V3, no FKs, idx (gathering_id, id)); `GatheringService.delete` deletes messages too. History `GET /api/gatherings/{id}/messages` (`?before=` 50 older, `?after=` fill after reconnect; 403 for non-participants incl. anonymous). Page `GET /gatherings/{id}/chat` (`chat/room.html` + `static/css/chat.css`; non-participant → detail + flash); detail shows "💬 모임 채팅" to participants. Client: reconnect backoff 1→30 s, `?after=` fill, dedupe by id, date dividers, grouped consecutive messages, textContent only (no innerHTML for user text), Enter sends (skips IME composition). **Tomcat closes a WebSocket with 1008 when its HTTP session ends (logout/expiry)** → client shows one combined "로그인이 풀렸거나 참여하지 않음" message and stops. Don't add `ServletServerContainerFactoryBean` (breaks MockMvc tests: no ServerContainer); Tomcat default text buffer 8 KB is enough. Not done: unread counts, notifications, delete/edit message, rate limit, multi-server (would need Redis pub/sub).
- Param validation: Spring 6.1 built-in method validation on `@RequestParam` (`@DecimalMin/@DecimalMax`) → 400.
- Kakao JS key is injected into all views by `global.config.ViewModelAdvice` as `kakaoJsKey`; templates load SDK with `autoload=false` and wrap code in `kakao.maps.load(...)`.
